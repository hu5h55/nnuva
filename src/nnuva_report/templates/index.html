Documentation & Guides

A media library quality optimizer for self-hosters

NNUVA looks at every video file in your Plex/Jellyfin/Emby library and asks two questions: Does it look good enough? and Is it bigger than it needs to be? The dashboard you're looking at is the answer, file by file, with a one-click ffmpeg or HandBrake command for anything you want to fix.

Who is this for?

Anyone running a media server at home with more than a few terabytes of content — typically Plex, Jellyfin, Emby, or Kodi setups. If you've ever thought "my library has gotten big, I wonder if I'm wasting space" or "is this 4K rip actually any good?", this tool is built for you.

The core idea: NQI scoring

Every file gets a Neutral Quality Index (NQI) score from 1 to 7 based on its actual encoding, not the filename or release group. NQI is the ratio of bitrate to what the resolution should reasonably need:

NQI 1–2 (Sub-quality) — bitrate too low for the resolution. The file looks blocky. Transcoding can't fix this; you need a better source.
NQI 3 (Acceptable) — meets baseline. Watchable, mobile-friendly.
NQI 4–5 (Optimal) — sweet spot. Good quality, reasonable size. Leave alone.
NQI 6–7 (Bloat) — bitrate way above what the resolution needs. These are your transcoding gold mines.

What this dashboard shows you

From top to bottom:

  • KPI cards — at a glance: total files, total storage, reclaimable storage if you transcoded the bloat tier, and counts in each NQI band. Each card opens a detailed breakdown popup.
  • Quality & Health charts — distributions across NQI tiers, resolutions, codecs, audio formats, HDR types, and a bitrate-vs-resolution scatter. Click any bar/segment to filter the library.
  • Library Explorer — file-by-file tables with sortable columns. Click any row to open the file detail modal.
  • File detail modal — NQI ratio bar, full media specs, copyable filename and directory path, and ready-to-run ffmpeg/HandBrake commands customized to that file.

Filters wire everything together

The search bar, the NQI quick chips, the chart clicks, the KPI breakdown rows — they all feed into one filter state. When something is filtering, the red bar appears at the top with the active filter pills. The library tables show only what matches. Hit the red × to clear everything.

Generating this dashboard

NNUVA is two CLI tools: a scanner and a report builder. They produce zero-dependency HTML you can serve from anywhere.

1

Install ffprobe

NNUVA uses ffprobe (part of FFmpeg) to read media metadata. On Debian/Ubuntu:

sudo apt install ffmpeg

macOS: brew install ffmpeg · Arch: sudo pacman -S ffmpeg

2

Scan your library

Run nnuva against any number of media root paths. It walks recursively, probes each file, and writes a cache to ~/.nnuva/ffprobe_cache.json. Subsequent scans only reprocess changed files — they're fast.

nnuva /mnt/media/movies /mnt/media/tv

Typical scan: ~1 second per 100 files on a fast disk.

3

Generate the dashboard

Compile the cache into a single HTML file with embedded data, charts, and styles — no server required, no external requests at runtime.

nnuva-report -o /var/www/html/nnuva.html

Or omit the path to write nnuva_report.html in the current directory.

4

Schedule it (optional)

Drop both commands into a cron job to keep the dashboard fresh. The Library Changes ledger (visible in the sparklines and the "since X" deltas) populates over time as snapshots accumulate.

# Run nightly at 3am 0 3 * * * /usr/local/bin/nnuva /mnt/media/movies /mnt/media/tv && /usr/local/bin/nnuva-report -o /var/www/html/nnuva.html

Where things live

~/.nnuva/ffprobe_cache.json — raw ffprobe output per file
~/.nnuva/nnuva.db — SQLite ledger of daily snapshots (powers the trend deltas)

Understanding what each section is telling you.

The KPI row (top)

Six cards summarize your library. The first three are size metrics (Total Files, Total Storage, Reclaimable). The last three are NQI tier counts (Optimal, Transcode, Upgrade). The little sparkline behind each card shows the 90-day trend; the meta line shows recent deltas. Click any card to open a detailed breakdown popup with per-resolution or per-codec splits and a CTA to filter the library.

Every chart is clickable — click a bar, segment, or scatter point to apply that as a filter. Click again to clear it. The Bitrate Distribution histogram lets you click a bucket to filter by bitrate range.

Library Explorer (bottom)

Quick NQI filter chips up top, then four tables that swap based on whether you have active filters:

  • No filters: shows three tables side by side — Transcode Targets, Upgrade Targets, Storage Hogs.
  • Filters active: shows a single Filtered Results table with everything matching.

Every column header is clickable to sort. Click again to flip direction. Click any row to open the file detail modal.

The file detail modal

The most useful view for taking action on a single file:

  • NQI Target Ratio bar — shows where this file sits on the Sub/Accept/Optimal/Bloat spectrum, with its actual ratio percentage.
  • Quantifiable Media Specs — eight tiles covering resolution, duration, FPS, bit depth, codec, HDR, and bitrates.
  • File Identity — filename and directory with copy buttons. Filename copy gives you something to web-search; directory copy gives you something to cd to.
  • Media Footprint radar — visual comparison of this file's size/bitrate/resolution/audio against the library's maximums.
  • Transcode & Downscale Actions — context-aware ffmpeg and HandBrake commands tailored to this file's NQI tier and codec.

Search

The search input at the top searches both filename and directory path. Pressing Enter scrolls down to the Library Explorer. Search is mirrored across the top bar, the floating header bar, and the inline search next to the NQI chips — type in any of them and they all sync.

Neutral Quality Index

NQI is a 1–7 score based on the ratio of a file's bitrate to a reference target for its resolution. The reference is calibrated against widely accepted "looks great at 1080p" / "looks great at 4K" baselines.

Important: NQI is about encoding appropriateness, not subjective quality. An NQI 7 file isn't "the best"; it's wastefully encoded. NQI 4–5 is the sweet spot you want most files to live in.

1

Critical (sub-baseline)

Bitrate is far below what the resolution can support. Heavy artifacting, blockiness. Common in old web rips. Transcoding will not help — find a better source.

2

Upgrade candidate

Below baseline. Probably watchable on a phone, painful on a TV. Worth replacing if the content matters.

3

Acceptable

Meets baseline. Fine for casual viewing, not premium. Often DVD rips or older streaming downloads.

4

Optimal (low end)

Good encoding. Web-DL or efficient Blu-Ray rips. Looks great on a 1080p TV with minimal storage cost.

5

Optimal (high end)

Excellent encoding. 4K Web-DL or well-encoded Blu-Ray. Top-tier picture, sensible file size.

6

Bloat

Bitrate exceeds what the resolution needs. Often Blu-Ray REMUXes. Transcoding to HEVC will roughly halve file size with negligible visible loss.

7

Extreme bloat

Unconscionable bitrate for the resolution. Almost always uncompressed REMUXes or experimental encodes. Highest-priority transcoding targets.

Best Practices

Codec choice

H.264 (AVC) is universally compatible — every device, every browser, every ancient TV. Use it when broad compatibility matters.
H.265 (HEVC) is the modern standard — about 50% better compression at equivalent quality. Use this when transcoding NQI 6–7 files to reclaim storage. Most hardware released after 2016 plays HEVC fine.
AV1 is the next generation — even better compression than HEVC, royalty-free, but software decoding is heavy and hardware support is still spotty. Worth experimenting with for archival.

Audio: the silent storage hog

Lossless audio formats (TrueHD 7.1, DTS-HD MA) can consume 2–4 GB per movie — sometimes more than the video itself. If you don't have a 7.1 home theater receiver actually decoding those tracks, transcoding to E-AC3 (Dolby Digital Plus) at 640 kbps sounds identical on soundbars, headphones, and most living-room setups, while saving terabytes across a library.

FFmpeg vs HandBrake

FFmpeg is unmatched for stream-copying — when you want to keep the video untouched but swap audio, drop unused audio tracks, or remux into a different container. Fast and surgical.
HandBrake is purpose-built for transcoding, with great built-in filters for cropping, deinterlacing, and subtitle burn-in. Use it when you're actually re-encoding video. The dashboard's transcode commands prefer HandBrake for NQI 6+ video transcoding and FFmpeg for audio surgery.

When to trust the NQI score (and when not to)

NQI assumes a "modern, well-encoded" codec like x264/x265 with reasonable settings. Some edge cases throw it off:

  • Animation — typically needs less bitrate than live-action for the same perceived quality. NQI may flag good animation rips as "Sub-quality".
  • Grain-heavy films — need higher bitrate to preserve grain. NQI may flag well-encoded film transfers as merely "Acceptable".
  • Dark/HDR content — modern HDR Blu-Rays use bitrate aggressively for shadow detail. Some legitimately optimal files land in NQI 6 territory.

Treat the score as a strong hint, not gospel. Always preview before committing to a transcode of irreplaceable content.

Glossary

Quality & encoding

NQI — Neutral Quality Index. NNUVA's 1–7 score for bitrate-appropriateness.
Bitrate — Data per second of video (Mbps). Higher generally = better quality but bigger file.
Resolution — Pixel dimensions. 720p, 1080p, 1440p, 2160p (4K), 4320p (8K).
FPS — Frames per second. Most movies are 23.976; broadcast TV is 29.97 or 25.
Bit depth — Color precision per channel. 8-bit is standard SDR, 10-bit is HDR.

Video codecs

AVC / H.264 — The dominant codec since ~2005. Universal compatibility.
HEVC / H.265 — Successor to H.264. ~50% smaller files at equivalent quality.
AV1 — Modern royalty-free codec. Better than HEVC but newer hardware only.
VP9 — Google's web codec, common on YouTube. Decent compression.
MPEG-2 — Old codec from the DVD era. Should generally be transcoded.

Audio codecs

AAC — Lossy, ubiquitous on streaming and YouTube.
AC3 / Dolby Digital — Older surround codec, very compatible.
E-AC3 / Dolby Digital Plus — Modern DD+, used by streaming services.
DTS — Lossy surround, often on Blu-Rays.
TrueHD — Lossless Dolby. Massive but mathematically perfect.
DTS-HD MA — Lossless DTS. Same idea as TrueHD, similar file sizes.
FLAC — Lossless audio, sometimes used in releases.

Source types

REMUX — Untouched 1:1 copy from a Blu-Ray/UHD disc. Largest possible file size, identical to source.
BDRip / BluRay — Encoded from a Blu-Ray. Smaller than REMUX.
WEB-DL — Downloaded directly from a streaming service. Untouched.
WEBRip — Re-encoded from streaming source.
HDTV — Captured from broadcast TV.
DVDRip — Encoded from a DVD. Always SD.

HDR formats

SDR — Standard dynamic range. The traditional 8-bit color space.
HDR10 — Open HDR standard. Static brightness metadata.
HDR10+ — Open HDR with dynamic per-scene metadata.
Dolby Vision — Proprietary HDR with dynamic metadata. Best on Dolby-certified TVs.
HLG — Hybrid Log-Gamma, broadcast-friendly HDR variant.
